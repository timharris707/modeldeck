# ModelDeck 1.1.13

Updating is smoother, and the Codex profile move can finally finish on a busy Mac.

**The deck no longer looks broken right after an update.** On the first start after 1.1.11, the deck sat on "Connecting to daemon…" for minutes while the background service was alive and merely busy cleaning up. Two fixes. The service now waits until it has served the deck once (or 30 seconds) before starting cleanup, and cleanup yields between batches so a data read always gets through. And when the service is answering but the first data read is slow, the deck says so in plain words: "The background service is busy after the update. The deck will fill in shortly." Gray, no warning colour, no repair button. (#673, #675)

**Release notes are readable inside the update dialog.** The notes you are reading now appear in the dialog above the Update Now button, scrollable, with an "Open on GitHub" link underneath. No browser needed to see what you are getting. (#675)

**Automatic update checks are on by default.** Automatic install was already on, but the check that feeds it shipped off, so a fresh install never checked at all. If you turned checking off, that choice is kept. (#675)

**The Codex profile move retries on its own and tells you what is in the way.** ModelDeck moves Codex profiles under its own folder, but it refuses while anything holds the old folder open. It used to try once at startup and then say "close Codex sessions and retry at next start", which is not something you can do with ChatGPT open all day. Now it retries every ten minutes, the deck shows one quiet line naming what is holding the folder ("Codex profile move is waiting on ChatGPT and codex"), and a "Move now" button runs it on demand. Process names only, never paths or command lines. (#676, #677)

**Also fixed**
- Settings → General's "Check for App Updates" no longer drops a click that lands during the background check. (#675)
